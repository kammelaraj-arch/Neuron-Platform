STEP 1

Flash MicroPython

One-off per Pico — installs the runtime our firmware needs.

  1. Unplug the Pico from USB.
  2. Hold the BOOTSEL button (white, on the Pico).
  3. While holding, plug it back into your laptop. A USB drive named RP2350 appears.
  4. Release BOOTSEL.
  5. Drag the file you'll download below onto the drive.
  6. The Pico reboots automatically and the drive disappears — that's normal.

STEP 3

Push the bundle to the Pico

On your laptop, with the Pico still on USB: 

pip install --user mpremote
unzip pico-bundle-{{ dna }}.zip
cd pico-bundle-{{ dna }}
mpremote connect auto cp boot.py main.py tmc.py config.json :
mpremote connect auto reset

After reset, the Pico:

  • connects to {{ wifi.ssid if wifi else '—' }}
  • scans the TMC bus, autodetects each driver chip
  • announces itself on UART (GP0/GP1) to the Pi 5
  • keeps motors disabled until the Pi 5 sends release

Communication channels baked into the bundle

Every Pico bundle ships with all four channels by default — CLAUDE.md "firmware default-channel contract". No operator opt-in needed; they exist from the moment the Pico boots.

Channel 1
Control (C2)
mTLS · port 8883 · recipe commands, parameter updates, telemetry uploads
Channel 2
Emergency
mTLS · port 8884 · separate cert · only safe_stop, safe_shutdown, status
Channel 3
OTA
HTTPS poll · hourly · base-version gated
Channel 4
UART (local)
GP0/GP1 · 115200 · parent Pi 5 link · always-on regardless of WiFi

Troubleshooting

mpremote: "no device found"
USB cable might be charge-only. Try a different cable (data-capable). On Linux you may need to add yourself to the dialout group.
"RP2350" drive never appears
You released BOOTSEL too soon. Unplug, hold BOOTSEL, plug in, keep holding for 2 sec, then release.
WiFi never comes up
Check the country code in config.json — Pico 2 W enforces regulatory limits. UK is "GB", US is "US".
TMC bus shows all "absent"
Wiring fault on GP4 (shared TMC UART). Check the half-duplex connection to all 3 drivers' PDN_UART pads.
