# Configuration Wizard — Canonical Spec (Smart-Factory / Edge / Gateway)

Authoritative spec for the device-configuration funnel. Updated 2026-05.
This is the wizard that drives FR-0005 (the device-registration funnel) and
the firmware-bundle builder (FR-0005 step 6). When this file disagrees with
code, this file wins until amended here.

## Hard rules (override anything below)

1. **Parent-only communication.** A child device (Edge / Gateway / Device)
   may ONLY talk to its parent. No inbound ports open on the child. All
   external requests reach the child via the parent's command-router.
   - Allowed flows: `Child → Parent` (outbound), `Parent → Child` (over the
     established mTLS session).
   - Disallowed: external → child direct, peer-to-peer between siblings,
     any open inbound port on the child.
   - Firmware bundle MUST emit firewall rules that deny all inbound
     traffic except loopback. SSH on the child is disabled by default;
     enabled only via the parent's reverse-proxy tunnel.
2. **The local brain is authoritative for safety.** Even when the parent
   link is alive, life-safety / critical interlocks are enforced by the
   on-device brain. The parent is advisory for these.
3. **Every state change auto-pushes up to the parent.** Fire-and-forget at
   the child; queued + replayed on reconnect.
4. **Bidirectional heartbeats** are mandatory. Loss of parent heartbeat
   for `disconnect_grace_seconds` triggers per-instance failsafes.

## Streamlined wizard funnel

The product-owner spec lists 18 steps. Several collapse onto one screen
without losing information (e.g. monitoring is a tick-list, not a step).
The implemented funnel is 10 steps, each mapping 1:1 to one URL under
`/ui/devices/wizard/{group_id}/<step>`. Spec-step numbers in `[]` below
are cross-references back to the 18-step product-owner spec.

### Step 1 — Role + target identity   `/role`
- **Role** (radio): Master · Edge · Gateway
- **Compute model** (select): rpi5_8gb, rpi5_16gb, rpi4, pico_2w, …
- **System name** (target name)
- **Description**
- **Location hierarchy**: factory → line → machine (free-text triples for
  v1; structured FK in v2)
- **Asset ID** *(mandatory)*
- **UUID**: blank at registration; auto-populated at provisioning when
  the firmware boots and reports its `cpuid` + `eth0 mac` to the parent.

### Step 2 — Compute pick   `/compute`
Identical to current step "Compute" — pin pool comes from compute_stable_id.

### Step 3 — Connectivity + access   `/connect`
- **Already connected?** Yes / No (branches form below)
- IF yes: capture `local_ip`, `ssid_seen`, `ip_type` (dhcp / static)
- IF no: capture **primary** + **secondary** WiFi (already implemented;
  Fernet-encrypted password, network-pool driven)
- **Hostname** / mDNS
- **External IP** (optional, behind-NAT advisory)
- **SSH** (host, port, username, password OR private key, sudo password —
  already implemented). Default = **disabled at boot**; the parent enables
  it on demand via the reverse tunnel.
- **USB fallback** (boolean — bundle includes a USB-gadget config so the
  device exposes a serial console + a Mass-Storage `config/` partition on
  USB-C; lets a tech rescue a brick'd unit without LAN access)
- **Bluetooth** (boolean — disabled by default for industrial)
- **NTP servers** (list, defaults to `pool.ntp.org`)

### Step 4 — Industrial protocols   `/protocols`
Tick which protocols the device speaks. Each enabled protocol opens a
sub-form. Persisted to `EdgeGroup.protocols_json`.

- **MQTT** *(mandatory for Master/Edge; default-on)*
  - broker_url, port, tls (bool), client_id, base_topic, qos
- **OPC-UA** (optional)
  - endpoint_url, security_mode, tag_mapping (JSON: `{"node_id": "label"}`)
- **Modbus TCP / RTU** (optional)
  - tcp: host + port; rtu: serial_port + baud + parity
  - registers (JSON: `[{"address": 40001, "kind": "holding", "label": …}]`)
  - slave_ids
- **CAN bus** (optional)
  - bitrate, can_iface (e.g. `can0`), filters

### Step 5 — Security   `/security`
- **Device certificate**: auto-generated by Master CA (default) OR upload
- **TLS** (bool, default on; can only be off on isolated test rigs)
- **API key management** — links to `/ui/secrets`
- **Roles**: Admin · Operator · Service (scope hierarchy already in code)
- **Hardening (auto-applied by firmware)**
  - Disable default `pi` user; create `neuron` w/ key-only login
  - Inbound firewall = deny-all; outbound allow-list to parent only
  - `fail2ban` for the SSH-via-tunnel port (1h ban after 3 fails)
  - Audit `journald → parent` shipper
- **Config lock (PIN)** — already implemented

### Step 6 — Boards / HATs   `/boards`
Current step. Adds: a **search box** keyed to the catalogue (already
present); drag-drop is *nice-to-have*, not v1.

### Step 7 — Components   `/components`
Current step. Adds:
- **Asset ID** input is now *mandatory* (was optional)
- **Direct-API devices** (smart plugs / cameras / Hue) get a sub-form for
  `api_endpoint` + `api_key` (the api_key is Fernet-encrypted via
  `secret_crypto`, never round-tripped to the browser)

### Step 8 — Pin map   `/pinmap`
Current step. Two sub-views:
- **8.1** Compute → HAT (existing canvas view)
- **8.2** HAT → Component (we already render this; add the toggle so
  operators can flip between sub-views)
Capture **signal type** + **control type** per pin (mostly auto-derived
from `signal_name` today — surface as editable fields).

### Step 9 — Local rules + telemetry   `/rules`
- **Rules engine**: list of `{when, then}` where `when` references a
  ComponentInstance + operator + value, `then` is `stop_motor / sound_buzzer
  / set_pwm(0) / publish_alarm`. Persisted to `EdgeGroup.rules_json`.
  Marked `critical=true` are enforced *locally only* (parent advisory).
- **Telemetry** tick-list: CPU · MEM · Temp · Disk · Uptime · Cycle-count
  · Fault-state. Sample interval per channel.
- **Alerts**: threshold-based + event-triggered. Routes to MQTT topic
  `factory/<factory>/<line>/<machine>/alerts`.

### Step 10 — Review + build + lifecycle   `/review`
- Review pane (existing) — adds Rules + Protocols summary
- **Deployment mode**: single · bulk · template (template = save the
  current group's config as a clone-source for future provisioning)
- **Group hierarchy**: factory → line → machine pickers
- **Build Golden Image** (the *big* artifact — see below)
- **Provisioning path** (radio): SD-card flash · remote (over SSH) ·
  USB-gadget fallback
- **Lifecycle actions**: OTA-update · Rollback · Decommission

## Golden image vs config bundle

Today's `group_bundle.py` emits a **config bundle** (DNA + Brain + WiFi +
manifest). The product-owner spec asks for a **golden image**: a bootable
OS disk image (base OS + all configs + protocol stacks + security
posture + first-boot script) that can be written to an SD card with
Etcher or `dd`.

Plan: layer the golden-image builder on top of the existing config
bundle. The image builder:
1. Starts from a pinned base OS (`pi-os-bookworm-arm64-2026-04.img.xz`)
   curated by the OTA gating doc.
2. Mounts the image (or builds from `pi-gen` for reproducibility).
3. Drops the existing config bundle at `/boot/neuron/`.
4. Drops a first-boot systemd unit `neuron-firstboot.service` that:
   - applies firewall rules,
   - disables `pi`, creates `neuron` w/ public key from bundle,
   - registers UUID with the parent,
   - schedules `neuron-agent.service` to start the C&C + emergency
     channels.
5. Writes a `golden-image-<dna>.img.xz` artifact alongside the config
   `.zip` and produces a torrent / HTTP URL for SD-flashing tools.

## Communication model in firmware

Encoded in `brain.json` (already partly done — see channels +
heartbeat). Adds:
- `inbound_policy: "deny"` — firmware writes `iptables/nftables`
  deny-all on input chain except loopback + the established mTLS
  outbound connection.
- `parent_only: true` — neuron-agent refuses to open any listener.
- `proxy_endpoint` — the parent URL the child opens its persistent
  channel to. mTLS, mutual cert pinning.
- `offline_policy.local_decision: true` — when parent loss exceeds
  grace, the brain enforces failsafe locally.

## Streamlining principles

- **One screen per decision class**, not one per field.
- **Defaults come from the catalogue manifest**, operator overrides only.
- **Mandatory fields are blocking** (cannot move forward); optional ones
  are skippable.
- **All inputs are idempotent** — re-running a step never destroys data,
  it only updates the EdgeGroup row.
- **Resume is first-class** — every step's URL is bookmarkable;
  `/ui/devices/wizard` always lists every group with status.
